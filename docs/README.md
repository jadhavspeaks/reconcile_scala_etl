# Data Reconciliation Framework (Scala/Spark)

## Overview

This framework provides a robust, Spark-based solution for data reconciliation, built with Scala and managed by Maven. It is designed to compare data from various sources (such as CSV, Excel, JSON, Parquet, ORC, Text files, and Hive tables) against other data sources, performing comprehensive validation checks.

The framework identifies discrepancies by performing row count checks, schema comparisons, detailed data matching based on primary keys, and column-level value comparisons.

## Features

*   **Versatile Data Source Support**: Ingests data from multiple file formats (CSV, Excel, JSON, Parquet, ORC, Text) and Hive tables.
*   **Flexible Schema Handling**: Supports schema inference or configuration-driven explicit schemas for source data.
*   **Comprehensive Reconciliation Checks**:
    *   Row count comparisons.
    *   Schema validation (column names and data types).
    *   Data matching on primary keys to identify matched, source-only, and target-only records.
    *   Column-by-column value comparison for matched records, with support for:
        *   Numeric tolerances.
        *   Case-insensitive string comparisons.
        *   Whitespace trimming.
*   **Business Rule Validation**: Executes custom SQL queries to validate business-specific conditions.
*   **Detailed Output & Reporting**:
    *   Stores reconciliation summary and detailed findings in Hive tables (`recon_summary`, `recon_details`).
    *   Optionally saves raw mismatch, source-only, and target-only DataFrames to HDFS.
    *   Generates HTML email notifications with status-colored headers (Green for Success, Red for Failure, Orange for Partial Success) and detailed summaries.
*   **Configurable Logging**: Utilizes SLF4J with Logback for flexible and configurable logging.
*   **Dynamic Configuration**: Fetches job configurations from a central API.

## Prerequisites

*   **Java Development Kit (JDK)**: Version 8 or higher.
*   **Apache Maven**: For building the project.
*   **Apache Spark**: Version 2.4.x (as configured in `pom.xml`), with Hive support enabled if interacting with Hive.
*   **Scala**: Version 2.11.x (as configured in `pom.xml`).
*   **Hadoop HDFS**: Required if using HDFS for input or output.
*   **Hive Metastore**: Required if reading from or writing to Hive tables.

*   **Configuration API**: An accessible API endpoint from which job configurations can be fetched.
*   **`RECON_API_KEY` Environment Variable**: For authenticating with the configuration API.

## Configuration

Reconciliation job configurations are fetched dynamically from an API endpoint at runtime. The application expects the API to return a JSON payload that maps to the Scala case classes defined in `src/main/scala/com/example/reconciler/config/ReconciliationConfig.scala`.

### Key Configuration Parameters (Scala Case Classes):

*   **`ReconciliationJobConfig`**: The root configuration object for a job.
    *   `jobId`: Unique identifier for the job.
    *   `jobName`: Descriptive name for the job.
    *   `sourceConfig`, `targetConfig` (`DataSourceConfig`): Defines the two data sources to compare.
        *   Can be `SourceFileConfig` (for files) or `SourceHiveTableConfig` (for Hive tables).
        *   Includes details like path, format, schema, database/table names.
    *   `primaryKeyColumns`: Sequence of column names for joining/identifying records.
    *   `columnsToCompare` (`ReconColumnConfig`): Specifies columns for value comparison, including tolerance, case sensitivity, etc.
    *   `businessRules` (`BusinessRuleConfig`): Optional list of SQL-based business rules to validate.
    *   `hdfsOutput` (`HdfsOutputConfig`): Optional configuration for HDFS output.
    *   `hiveOutput` (`HiveOutputConfig`): Optional configuration for Hive output.
        *   `databaseName`: Target Hive database.
        *   `summaryTableName`: Name for the comprehensive summary table (e.g., `recon_summary`).
        *   `mismatchTableName`: Name for the raw value mismatches table (may be deprecated in favor of `detailTableName`).
        *   `detailTableName`: Optional. Name for the table storing detailed event logs (e.g., `recon_details`). If provided, detailed logs are written.
    *   `emailNotifications` (`EmailConfig`): Configuration for email alerts.
*   **API Authentication**: The application expects an API key to be provided via the `RECON_API_KEY` environment variable for authenticating with the configuration API.

### Example `spark-submit` Command-Line Arguments:
The application accepts the following command-line arguments:
1.  `jobId` (String, mandatory): The ID of the reconciliation job to run. This ID is used to fetch the configuration from the API.
2.  `apiBaseUrl` (String, optional): The base URL for the configuration API. If not provided, it checks Spark configuration `spark.reconciler.apiBaseUrl`, then defaults to a placeholder (which will show a warning).

## Running the Application

Submit the packaged JAR to Spark using `spark-submit`.

```bash
# Example:
export RECON_API_KEY="your_actual_api_key" # Set the API key environment variable

spark-submit \
  --class com.example.reconciler.Main \
  --master <your_spark_master> \ # e.g., yarn, local[*]
  --deploy-mode <client_or_cluster> \
  --name "Recon_Job_${JOB_ID}" \
  target/data-reconciliation-framework-1.0-SNAPSHOT.jar \
  ${JOB_ID} \ # First argument: Job ID
  http://your-config-api-host/api/configs # Second argument (optional): API Base URL
```

*   Replace `<your_spark_master>` and `<client_or_cluster>` with your Spark environment specifics.
*   The JAR name in `target/` might vary based on Maven configuration.
*   `${JOB_ID}` should be the specific job ID you want to run.
*   Provide the actual configuration API base URL if it's not set via Spark config.

## Logging

The framework uses **SLF4J** with **Logback** for logging.
*   Configuration is managed via `src/main/resources/logback.xml`.
*   You can customize log levels, appenders (console, file, etc.), and log formats in this file.
*   By default, it logs to the console. Application logs for `com.example.reconciler` are set to `INFO`, and Spark logs are generally set to `WARN` to reduce verbosity.

## Output and Reporting

### HDFS Output
If configured in `ReconciliationJobConfig.hdfsOutput`, the framework can save:
*   The full `ReconciliationJobSummary` object as a JSON file.
*   DataFrames for value comparison mismatches, source-only records, and target-only records in specified formats (e.g., Parquet, CSV).

### Hive Tables
If configured in `ReconciliationJobConfig.hiveOutput`:
1.  **Summary Table (e.g., `recon_summary`)**:
    *   Stores one comprehensive row per reconciliation job run.
    *   Includes: `job_id`, `job_name`, `overall_status`, timings, source/target names, and summary statistics from all reconciliation stages (row counts, schema checks, data matching, value comparisons, business rules).
2.  **Details Table (e.g., `recon_details`)**:
    *   Enabled if `hiveOutput.detailTableName` is specified.
    *   Stores fine-grained details about discrepancies, with each row linked by `job_id`.
    *   `detail_type` column indicates the type of detail (e.g., `SCHEMA_MISMATCH`, `VALUE_MISMATCH`, `SOURCE_ONLY_KEY`, `TARGET_ONLY_KEY`).
    *   Includes relevant data like primary keys (as JSON), attribute name, source/target values, and remarks.
3.  **Mismatch Table (e.g., `job_mismatches_raw`)**:
    *   The original table for storing raw value comparison mismatches. This might be deprecated in the future if all details are consolidated into the `recon_details` table.

### Email Notifications
If configured in `ReconciliationJobConfig.emailNotifications`:
*   HTML email reports are sent summarizing the reconciliation outcome.
*   The main header of the email is color-coded based on the overall status:
    *   **Green**: Success
    *   **Red**: Failure
    *   **Orange**: Partial Success
*   The email body includes detailed summaries of each reconciliation step.

## Key Modules/Packages (Scala)

*   **`com.example.reconciler.Main`**: Main entry point for the Spark application. Orchestrates configuration loading, reconciliation execution, and output generation.
*   **`com.example.reconciler.config`**: Contains Scala case classes for configuration (`ReconciliationJobConfig`, `DataSourceConfig`, etc.) and `OracleConfigFetcher` for retrieving configurations from an API.
*   **`com.example.reconciler.models`**: Defines data models (case classes like `ReconciliationJobSummary`, `ReconStatus`, `RowCountReconResult`) used to represent reconciliation states and results.
*   **`com.example.reconciler.readers`**: Includes `DataSourceReader` trait, implementations (`FileDataSourceReader`, `HiveDataSourceReader`), and `DataSourceReaderFactory` for reading data from various sources.
*   **`com.example.reconciler.services`**:
    *   `ReconciliationService`: Core logic for all reconciliation steps (row count, schema, data matching, value comparison, business rules).
    *   `OutputService`: Handles writing reconciliation summary and details to HDFS and Hive.
    *   `EmailService`: Manages the generation and sending of HTML email reports.
